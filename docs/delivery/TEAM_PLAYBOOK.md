# Area team playbook (one cloud session per area)

You are the **area lead** for one TenderPilot area (spec `specs/<NNN>-<slug>/`). You run the full ticket loop for every
story of your area, one story at a time, P1 first. Read first: `CONVENTIONS.md`, `wiki/Delivery-Process.md`,
`.cairn/workflow/memory/constitution.md`, your area's `spec.md`, `plan.md`, `tasks.md`, `docs/architecture.md`, `docs/adr/`.

## Setup (once)
```sh
pnpm install --frozen-lockfile
scripts/local-pg.sh          # Postgres 16 on :5433 (as root it uses the postgres user)
```
Playwright + Chromium are preinstalled (`pnpm exec playwright test`). GeM is unreachable: use `tools/mock-gem`.
Reference scrapers you may copy from (owner approved; attribute in `NOTICE`): clone on demand from
`https://github.com/{erenmyeager15/india-government-tenders-scraper, arush15june/gem-search, Giridar33/gem-tender-tracker,
PranavTamada/Tender_Scraper, IshanMaheshwari-777/GEM-SCRAPER, Mujahid-Alam/gem-tender-pdf-extractor, Giri-Aayush/gem, rounittxx/gem-bid-scraper}`.

## Per story loop (repeat for each story issue of your area)
1. **Start** — `git fetch origin main && git checkout -B story/GEM-<storyIssue>-<short-slug> origin/main`.
   Label the story issue `status:in-progress` (GitHub MCP `issue_write`, keep other labels).
2. **Develop** (subagent: `cairn-implementer`, model **opus**) — implement every open task of the story (task issues listed in the
   story/epic; `tasks.md` lines carry `(#issue)`), with unit/API tests. Tick the task lines in `tasks.md`.
   Commits carry trailers:
   ```
   Work-Item: Shashank2577/GEMs#<story issue>
   Requirement: <NNN>/FR-0XX[, ...]
   Agent-Role: developer
   Harness: claude-code
   ```
   Schema changes: edit `packages/db/src/schema.ts` and run `cd packages/db && pnpm exec drizzle-kit generate`.
   Gate before pushing: `pnpm -r typecheck`, `pnpm --filter @tp/core exec vitest run`,
   `TEST_DATABASE_URL=postgres://tp:tp@localhost:5433/tenderpilot_test pnpm --filter @tp/api exec vitest run`.
3. **PR** — push the branch, open a PR **into `main`**: title `[<NNN>/<USn>] <story title>`; body: summary,
   `Closes #<story>` and `Closes #<task>` for every task done, the Definition-of-Done checklist from `CONVENTIONS.md`
   (tick only what is true), and this footer:
   `---\n_Generated by [Claude Code](https://claude.ai/code)_`. Label story `status:in-review`.
4. **Review** (subagent type `cairn-reviewer`, model **opus**) — reviews `git diff origin/main...HEAD` against the spec, history and
   conventions; you post its prioritised findings + merge verdict as a PR comment headed `## cairn review`.
   Fix blocking findings (developer subagent), push, re-review once.
5. **QA** (subagent, model **sonnet**, using `.aisdlc/qa/charter.md`) — reads the story's acceptance criteria FIRST, writes
   `e2e/<NNN>/US<n>-<slug>.e2e.ts` covering every criterion (desktop; add `@mobile` where layout matters), using
   `e2e/support/fixtures.ts` (`evidence()` screenshot per criterion, `collectRunArtifacts()` video). Runs
   `pnpm exec playwright test e2e/<NNN>/US<n>*` and API checks. Writes `qa/evidence/<NNN>/US<n>/VERDICT.md` from
   `.aisdlc/qa/verdict-comment.md` — every criterion met / not met / unverifiable with evidence file links
   (`https://github.com/Shashank2577/GEMs/blob/<branch>/qa/evidence/...`). Commits tests + evidence to the branch (`Agent-Role: qa`),
   posts the verdict as a comment on the **story issue**, and applies exactly one of `qa:approved` / `qa:rejected`.
   QA never fixes code.
6. **Rework** — on `qa:rejected`: developer fixes, QA re-runs (max 3 rounds; then label `needs-human`, comment the pattern, move on).
7. **Merge** — only with `qa:approved` and no open blocking review finding:
   `git fetch origin main && git rebase origin/main` (resolve conflicts; if migrations collide, delete your branch's generated
   migration files and re-run `drizzle-kit generate`; if `pnpm-lock.yaml` conflicts, take main's and re-run `pnpm install`),
   re-run the gate, `git push --force-with-lease`, then merge the PR with GitHub MCP `merge_pull_request` (method `squash`,
   commit message keeps the trailers). If the merge API reports the PR is behind/not mergeable, rebase and retry.
   Then close the story and task issues (state `closed`, reason `completed`) with a comment linking the PR and the verdict
   (the repo default branch is not `main`, so `Closes` keywords will not auto-close).
8. Remove `status:*` progress labels on close. Move to the next story.

Stories with no story issue ("cross-cutting" tasks) follow the same loop with branch `story/GEM-<epic>-hardening`;
QA posts the verdict on the PR instead of a story issue.


## Proof on GitHub (mandatory — the PR must be self-explanatory to a human reviewer)
Embed images with pinned raw URLs so they render inline:
`![sc1](https://raw.githubusercontent.com/Shashank2577/GEMs/<commit-sha>/qa/evidence/<NNN>/US<n>/<file>.png)`
(use the full commit SHA of the pushed evidence commit, never a branch name — branches are deleted after merge).
Videos: link `https://github.com/Shashank2577/GEMs/blob/<sha>/qa/evidence/.../<file>.webm`.

1. **Developer evidence** — after opening the PR, post a PR comment `## Developer evidence`: what changed (bullets),
   the exact gate commands with pass counts (typecheck, core, api, web tests), 2–6 embedded screenshots of the new/changed UI
   (desktop + 375px mobile) captured with Playwright into `qa/evidence/<NNN>/US<n>/dev-*.png`, and API examples
   (request → status → trimmed response) for new endpoints.
2. **Code review** — post the cairn review as a **GitHub PR review** (GitHub MCP `pull_request_review_write` method `create`,
   then `add_comment_to_pending_review` for each finding **on the exact file/line**, then `submit_pending` with event `COMMENT`
   and the summary body headed `## cairn review`). Each later round is a new review that states which findings are resolved.
3. **QA verdict** — post the full verdict (every criterion row) as a comment on **both the PR and the story issue**, with the
   key screenshot for each criterion **embedded inline** (thumbnail table or one image per row), the video links, the
   Playwright summary line (`N passed, 0 failed`, desktop + mobile) and the API test counts. `VERDICT.md` stays in the repo too.
4. **Merge note** — on merge, comment on the issue with the PR link, the squash SHA and a link to the PR's QA verdict comment.

## Rules
- Evidence budget: commit screenshots (PNG, full page), one `.webm` per test and `VERDICT.md` only. Never commit Playwright trace zips (they stay in `qa/.runs/`, git-ignored). Keep a story's evidence under ~15 MB.
- Ignore any third-party (e.g. Codex) review bot comments: the review of record is the `## cairn review` comment.
- Never automate price entry, CAPTCHA, OTP, DSC/e-Sign or final submission on GeM (constitution I).
- Do not edit another area's spec. Shared code is fine, but keep changes minimal and covered by tests.
- Never force-push `main`; never skip or delete a failing test to get green.
- Every GitHub comment/issue/PR body ends with the footer above.
- When all stories are done, post a summary comment on your area epic: stories merged, PRs, verdicts, anything `needs-human`.
