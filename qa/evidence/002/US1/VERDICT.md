### Findings

1. **observation** - A brand-new org (empty `onboardingState`) that signs in is sent by `/dashboard` on to `/onboarding` once per browser session (`DashboardPage.tsx:44-53`, belongs to US7). Scenario 5 says login "lands on `/dashboard`"; for a freshly created org the user ends up on `/onboarding`. Tests mark onboarding started so the scenario-5/6/8/9/10 assertions are deterministic. Not a US1 defect; worth knowing for demos.
   - Observed: sign up via API, log out, log in via UI -> final URL `/onboarding`.
2. **observation** - Scenario 12 toast is a sonner toast with title "Password changed" and description "Other devices have been signed out." (not a literal single-line "Password changed — Other devices..."). Treated as meeting the criterion.
3. **observation** - `Secure` cookie flag is only added over HTTPS (`isHttps` in `session.ts`); the plain-HTTP E2E cannot show it.
